Install lockmq

lockmq runs in Docker: nothing to install on your machine but Docker. The image holds the separated setup: the console as lockmq, the agent as agent in lockmq-clients, a root-owned /etc/lockmq/system.toml and the socket directory shared through a named volume. Other deployment modes exist in the code but are no longer documented.

lockmq is a pre-release (v0.1.x): the CLI, the MCP tools and the config files may still change before v1.

1. Build the image

docker build -t lockmq https://github.com/DavidGodefroid/lockmq.git

Or docker build -t lockmq . from a clone. The base images are pinned by digest. docker build --target vault -t lockmq . adds the Vault CLI, checked against pinned sums, for credentials = "vault".

2. Set up a project

Mount the project at its own path: the console and the agent must see the same one. In the project directory, the agent files, then a broker profile:

docker run --rm --user "$(id -u):$(id -g)" -e HOME=/tmp -v "$PWD:$PWD" -w "$PWD" lockmq init claude
docker run -it --rm --user "$(id -u):$(id -g)" -e HOME=/tmp -v "$PWD:$PWD" -w "$PWD" lockmq setup

setup asks for the management API URL, the optional AMQP and stream URLs, the vhosts, the user, where the password comes from (ask or vault; never the password itself), production or not, and whether to allow queue peeks (default no). In a container localhost is the container itself: a broker on your machine is host.docker.internal, a broker container is its name on a network shared with the console.

Then give .lockmq/ to the console account, as root in the image (the repair never follows a symbolic link):

docker run --rm --user 0 -v "$PWD:$PWD" -w "$PWD" lockmq doctor --fix --yes

3. Create a read-only broker user

Tag it monitoring, give it empty configure and write permissions, and read only on what lockmq may read. RabbitMQ lets read purge a queue: grant it on the streams, and on queues only for profiles with tier peek.

rabbitmqctl add_user lockmq-ro 'choose-a-password'
rabbitmqctl set_user_tags lockmq-ro monitoring
rabbitmqctl set_permissions -p orders lockmq-ro '^$' '^$' '^(order-events)$'

4. Start the console

In a terminal you keep in view, from the project directory (add --network NAME for a broker container):

docker run -it --rm --name lockmq-console --user lockmq -v "$PWD:$PWD" \
  -v lockmq-run:/run/lockmq -v lockmq-home:/home/lockmq lockmq console --project "$PWD"

It checks the isolation, asks you to approve the policy, asks for the password (or reads Vault), connects, audits the broker user’s privileges and opens the socket.

5. Wire your agents

The agent starts the MCP server in a throwaway container, as agent, with the socket volume and the project:

claude mcp add --scope user lockmq -- \
  sh -c 'exec docker run -i --rm -v "$PWD:$PWD" -w "$PWD" -v lockmq-run:/run/lockmq lockmq mcp'

Codex, Gemini CLI and Cursor take the same command; an agent in a container of its own, without the Docker socket, runs lockmq as a client of the console container. The full Docker guide · every command in the usage guide.
