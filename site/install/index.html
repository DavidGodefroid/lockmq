Install lockmq

lockmq runs in Docker: on your machine, Docker and one lockmq command, a launcher that runs every command in the signed release image with the account it needs. The image holds the separated setup: the console as lockmq, the agent as agent in lockmq-clients, a root-owned /etc/lockmq/system.toml and the socket directory shared through a named volume.

lockmq is a pre-release (v0.1.x): the CLI, the MCP tools and the config files may still change before v1.

1. Install the launcher

V=vX.Y.Z
curl -fsSLO "https://raw.githubusercontent.com/DavidGodefroid/lockmq/$V/scripts/install.sh"
less install.sh
LOCKMQ_VERSION=$V sh install.sh

It checks the release’s cosign signature and checksum, and the image’s signature, then installs /usr/local/bin/lockmq, pinned to the verified image digest. lockmq version prints the launcher’s and the image’s versions; lockmq update updates both. LOCKMQ_VAULT=1 selects the image with the Vault CLI, for credentials = "vault"; LOCKMQ_IMAGE runs your own build. On Windows, install it in WSL 2.

2. Set up a project

In the project directory, the agent files, then a broker profile:

lockmq init claude
lockmq setup

setup asks for the management API URL, the optional AMQP and stream URLs, the vhosts, the user, where the password comes from (ask or vault; never the password itself), production or not, and whether to allow queue peeks (default no). In a container localhost is the container itself: a broker on your machine is host.docker.internal, a broker container is its name on a network shared with the console.

Then give .lockmq/ to the console account; the launcher runs the repair as root in the image (it never follows a symbolic link):

lockmq doctor --fix --yes

3. Create a read-only broker user

Tag it monitoring, give it empty configure and write permissions, and read only on what lockmq may read. RabbitMQ lets read purge a queue: grant it on the streams, and on queues only for profiles with tier peek.

rabbitmqctl add_user lockmq-ro 'choose-a-password'
rabbitmqctl set_user_tags lockmq-ro monitoring
rabbitmqctl set_permissions -p orders lockmq-ro '^$' '^$' '^(order-events)$'

4. Start the console

In a terminal you keep in view, from the project directory (LOCKMQ_DOCKER_ARGS="--network NAME" for a broker container):

lockmq console

It checks the isolation, asks you to approve the policy, asks for the password (or reads Vault), connects, audits the broker user’s privileges and opens the socket.

5. Wire your agents

lockmq init claude wired Claude Code to lockmq mcp: the launcher starts the MCP server in a throwaway container, as agent, with the socket volume and the project. For every project instead:

claude mcp add --scope user lockmq -- lockmq mcp

Codex, Gemini CLI and Cursor take the same command; an agent in a container of its own, without the Docker socket, runs lockmq as a client of the console container. The full Docker guide · every command in the usage guide.
